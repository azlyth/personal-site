# Editor: paragraph alignment and a Link button

Date: 2026-11-15. Approved by Peter (alignments: Left and Center only).

## Why

Peter wants to centre individual paragraphs (a lone call-to-action URL at the
end of a post) and to make text into links without typing markdown. A bare
URL on its own line is not clickable on the blog today (Zola doesn't
autolink), so the link tool fixes a real dead link too.

## Design

### Alignment

- On disk a centred block is a wrapper with markdown inside, blank lines
  around the prose (CommonMark only parses markdown in an HTML block once a
  blank line closes it -- same mechanism the pair uses):

  ```
  <div class="align-center">

  <the block's markdown, unchanged>

  </div>
  ```

  Left is the default and writes no wrapper, so every existing post stays
  byte-identical.
- `editor/blocks.py` groups opener + prose + closer into ONE block of a new
  kind (or a flag on the inner kind) the way `_group_pairs` folds a pair,
  matching on the opener's source; an opener without a closer stays
  ungrouped. The block reports `align: "center"` and its inner markdown;
  editing the text edits the inner markdown only, and the wrapper is
  regenerated byte-exactly (lossless round-trip test, same discipline as
  `parse_images`).
- Allowed for paragraph, heading, list and blockquote blocks; not for pairs,
  media rows, spacers.
- Edit bar (open text block): a two-way toggle `Left | Center` (icons) in the
  settings group; saved with the text on Done, like other bar settings.
- `templates/base.html`: `.align-center { text-align: center; }` (and its
  list markers should still look right -- centre a list's text, keep bullets
  attached). `editor/web/editor.css` mirrors it so the editor preview shows
  the alignment; a test asserts both files define the class.

### Link button

- A 🔗 button in the edit bar's settings group while a text block is open
  (text, heading, list, blockquote, and a pair's prose field).
- With a selection in the field:
  - if the selected text is itself a URL (`https?://...` or `www....`, no
    spaces), replace it with `[<text>](<url>)` (adding `https://` to a bare
    `www.` target) in one tap;
  - otherwise ask for the URL (a small inline input above the bar with
    `Add link` / `Cancel`, prefilled with a URL from the clipboard when
    readable), then write `[<selection>](<url>)`.
- With no selection: insert `[link text](<url>)` at the caret with
  `link text` selected.
- The edit goes into the textarea as a normal edit (dirty, draft backup,
  saved on Done, Undo-able), keeping focus and putting the caret after the
  link. The button must not steal focus/selection (mousedown preventDefault,
  like the bar's other controls).

## Testing

- pytest: alignment round-trip (parse -> regenerate == original) for a
  centred paragraph, heading and list; an unclosed opener stays ungrouped;
  saving text edits keeps the wrapper; Left removes it; the CSS class exists
  in both base.html and editor.css; existing posts parse byte-identically.
- `scripts/verify-edit-tap.py`: open a paragraph, toggle Center, Done ->
  file has the wrapper and the block renders centred; reopen, toggle Left ->
  wrapper gone. Select a URL and tap 🔗 -> `[url](url)`; select words, tap
  🔗, enter a URL -> `[words](url)`; focus stays in the field.
- A Zola build: the centred paragraph renders as a centred `<p>` with a
  working `<a>`.
